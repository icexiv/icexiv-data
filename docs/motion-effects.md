# 动作与特效的数据链

群星手锯（51778）的静态外观和运动中的挂点需要分开验收。锯柄三环、锯刃和
锯背外框在固定姿态的缺失，已由 renderer 的深度偏移方向和 IMC 子网格掩码解释。
这个结果不能回答“手腕转过九十度时，光环是否仍在正确的位置”。

## 群星手锯：从骨骼到挂点

`w5004/b0008` 的 `vw0004.avfx` 有一个 Point binder。Start 指向宿主的
ElementId 3，父骨名为 `n_hara`，在武器所选骨架中是骨 1。Data 中只有一条
`SpS`，只有第 0 帧的一个 key，三个值均为 1。因而不能把这块未参与播放
直接解释为“丢了一条随时间摆动的轨迹”。此例最有区分力的检查是：

1. 用同一帧的最终局部骨姿态和 ElementId 平移计算骨架空间挂点，先对比数值。
2. 给宿主单独施加旋转和非均匀缩放，比较光环中心、朝向和尺寸。Win32 坐标查询成功的分支
   把 `bFTO=0xff` 解释为保留归一化基轴，把 `bTSc=1` 解释为保留独立三轴长度。
   平移不随 `bFTO` 清除；`host_frame` 对提供的宿主帧执行这一步。`CoUF=-1`
   使 Start 不受截止帧限制：已进入坐标更新路径时仍可查询宿主，而非冻结在出生帧。
   外层实例是否活动、查询是否成功是另外的条件。
3. 只在位置一致后比较亮度和边缘；`bATM` 色调映射与软粒子深度淡出属于绘制端。

## 各环节能交给调用者什么

| 环节 | data 输出 | 完整播放还需要什么 |
| --- | --- | --- |
| 装备常驻挂载 | IMC 变体、VFX ID、子网格掩码；MDL ElementId 名称与局部偏移 | 宿主按实际部件选择资源、应用掩码；持握动作还需要角色与武器两套骨架之间的装配 |
| 动作与事件 | Action 行→ActionTimeline key、独立 TMB 与 PAP 内嵌 TMLB；从 actor、track 的 ID 列表定位可达命令，读动画名、子时间线、特效与声音引用。C012 提供两个绑定目标、TRS、RGBA、可见性原值 | 命令触发条件、多个 actor 的时钟、子时间线的播放与取消策略。列举所有 C012 与沿可达轨道列出的是不同查询 |
| 单片段姿态 | spline 按毫秒采样，显式轨道映射生成稀疏骨姿态；给定最终局部姿态可计算骨架空间挂点 | 加法层、转场权重、根运动、重定向及缺省映射；未验证的 float tracks 与压缩变体需要单独样本 |
| AVFX 运动 | 调度器和时间线引用、发射器/粒子/绑定器变体；标量和 RGB 各自的插值与边界；六种标量随机幅度模式、显式随机流；Point 常量、CoUF 截止帧与宿主坐标分解 | 全场景共享随机流的初始状态与消费顺序、粒子更新顺序、Start/Goal 的宿主与生命周期 |
| 画面 | 内嵌网格、纹理与绘制字段 | 播放器生成实例；renderer 负责相机、排序、深度、软粒子和色调映射 |

对接时应核对**实际依赖修订**：关联会话中的 `icexiv-renderer/effects/Cargo.toml`
把 `assets` 固定到 `7fa1b24b` 的 `game-data` 接口。这个工作区的接口是
`avfx`、`pap`、`havok`；这里的测试通过不表示固定依赖的播放器已调用它们。

## 技能特效和持武器姿态的实例

**飞石**：Action 119 → ActionTimeline 448 → `magic/cnj_white/stone` →
`chara/action/magic/cnj_white/stone.tmb`。TMAC 2 的 TMTR 6 引用 C012 13，
起点 2、时长 30；路径为 `vfx/action/mgc_stone1/eff/mgc_ston1t0h.avfx`。
两个目标配置分别为施术者与目标的角色，绑定 ID 均为 −1。C010 动画名为
`cbbm_mgc_cnj_3b`。同一资产还引用 `battle/magic_cnj_end`；该子时间线有两个
独立 C012，资源路径相同，第一绑定点却分别选择武器和副手。按 AVFX 路径去重会丢掉一次挂载。

**站姿**：`normal/idle.tmb` 的 C010 指向 `cbnm_id0`；在人族 c0101 的
`bt_common/resident/idle.pap` 中对应 Havok index 1。按显式骨映射采样并沿父链
合成后，骨 87 `n_buki_r` 提供三个基向量和挂点位置。它们是**角色骨架空间**
的结果；武器 `n_hara` 则在武器自己的骨架内。两骨架之间仍需明确的持握变换。

## 验收优先级

| 优先 | 能区分故障的输入与观测量 | 责任 |
| --- | --- | --- |
| 手锯动态挂点 | 对同一帧依次记录角色 `n_buki_r`、武器根、`n_hara`、ElementId 3、binder 输出轴与 scale，以及三个环的中心。第一个不吻合的空间决定该查持握装配、绑定参数还是绘制 | data 给出骨架帧与坐标分解；播放器提供两套骨架之间的变换和刷新时点 |
| 单技能播放 | 飞石从动作行、主/子 TMB 到 C012。断言 actor/track/command ID、局部时间与两个绑定目标；同路径的两条挂载不能合并。与游戏对比的应是触发帧及挂点，而不是文件中出现几次路径 | data 提供依赖和参数；播放器解释条件、取消、循环、源/目标对象的生命周期 |
| 多层动作 | 单独记录普通层、加法层与最终骨帧，验证缺失骨、过渡权重、根运动、重定向和武器挂持；只有明确的独立组合结果才能判定 blendHint 的消费语义 | data 解码各层；混合规则与参考姿态的证据不能用单层采样代替 |
| 其余特效配置 | 按实际 AVFX 检查随机曲线、颜色、不同 binder/effector 及父子发射器；逐帧比较实例数、局部变换、颜色、UV 和生灭时间，再交给 GPU | 文件解码和曲线数学属于 data；模拟与最终着色分别由播放器和 renderer 负责 |

详见 [PAP 布局](pap/README.md)、[AVFX 布局](avfx/README.md)和
[实资源及 REA 证据](provenance/motion-effects.md)。
