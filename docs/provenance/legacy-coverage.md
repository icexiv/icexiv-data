# Legacy 解析能力的隔离对照

## 审计范围与来源

用户授权隔离子会话对 `legacy/` 的公开入口、文档、测试定义及必要实现
作功能审计。实现内容留在审计子会话；实现会话只接收能力范围、文件位置、
来源与证据等级，不读取、复制或移植归档实现。归档文件及其许可/来源
声明保持原样；项目发布状态和许可证决定见[方法与边界](README.md#方法与边界)。
此流程不构成严格 clean-room 声明。

对照基线为 `research/render-blockers` 工作树中的活动库公开接口、README
与[需求清单](../requirements-coverage.md)。legacy 的实现存在性、受控测试
定义和留存生产输出分别记录；本项没有运行 legacy，也不把其输出用作
活动库的独立 oracle。

## 常用文件能力

SqPack/EXH/EXD、MDL/SGB、MTRL/SHPK/STM、TEX/ATEX、IMC/EQP/CMP、
SKLB/Havok/PAP 和 AVFX 的需求内解析输出均有活动库对应接口，实际资源
验证范围由各格式来源页给出。该对照支持常用解析基础的接入验证，不代表
旧调用清单与全部目标资源已逐项迁移验收。

MDL 单/双分量浮点是审计指出的具体解码集合差项，功能位置为
`legacy/src/formats/mdl/geometry.rs:456–505`。活动实现以独立客户端映射和
官方数值规格确立身份，数值与边界验证见[MDL 证据](mdl.md#binary32-布局与位保留验证)。
legacy 审计没有回传分派常量或算法，也没有提供这两种类型的生产样本成功记录。

### MDL / SKLB 的非实现来源核对

`../icexiv-data-evidence/historical-input-sources-20/REPORT.md` 记录两次
预声明精确搜索及两个文档候选的元数据核验。Ioncannon 格式研究页仅有
二手引用，元数据未建立作者/许可及技术正文身份；MultiAssist 的历史资源
提取教程提供 `m0512` 骨架路径线索，但页面日期没有绑定游戏构建、文件
哈希或额外容器类型。两处许可均为未知，未批准为兼容编码规格。

实现/API 搜索命中的意外摘要接触留在隔离账本；主会话只接收来源、位置与
证据等级，没有接收编码常量、字段宽度或算法。净化报告为 6419 字节，
SHA-256 为 `d4f82b68954a32deb1d06351ba9fd9679802c247959b35fe365fcc200b98a5d6`。
这个有界范围没有建立历史候选的必要输入身份，不推论所有历史资料或文件
不存在相应定义，也不改变已登记生产文件的解析验证结论。

## 语义与上层能力

PBD 完整 source/target/bind 空间、EQP 全部显隐条件及特殊变体语义没有
找到 legacy 的独立完整验收证据。活动库保留这些语义边界，不将其直接
计为迁移退步。除已知短 volume 外，此次静态审计没有找到另一个“旧库有
已验收生产输入成功、新库却无法读取”的见证；这不是对所有输入的证明。

角色装配、路径业务回退、姿态/蒙皮、材质烘焙、VFX 模拟、目录导出和 CLI
属于上层范围。解析能力对照不据此宣称整个 legacy 已替代。
