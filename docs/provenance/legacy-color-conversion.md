# Legacy 色行转换的静态证据

## 来源、对象与方法

对象是 Win32 安装 `2026.10.06.0000.0000` 的内嵌 MTRL 色表消费路径。
授权只读的 Win64 `ffxiv_dx11.exe` 为 51910400 字节，SHA-256：
`958b78e278ad896493c484eb313ff605ab41edefef74f92b0ee078e69b281bf9`，
PE 首选 image base 为 `0x140000000`。下文地址均为首选 VA。

指令观察使用 GNU objdump 2.46。REA 原生引擎不可用的限制沿用
[来源记录](materials.md)，这里没有 REA Evidence、运行观察或目标函数仿真。
阅读范围是本页列出的程序区间、常量和已登记实际材质，没有读取 `legacy/`。
Rust 输出采用本项目的定点数学与不可变表操作；没有移植客户端分配、缓存
或指令控制流。公开资料检索的接触范围见本页末尾。
本页保留审阅接触，不宣称严格 clean-room；程序和资源字节留在仓库外。

研究问题是 **16-half 源行如何成为 32-half 中间行**，以及哪些常见简化
能被静态数据流和真实源值区分。源行数值、静态路径语义、公式推论和
实际转换输出是不同证据层次；源值投影实验只涵盖前两项。库的完整输出与
独立数学对照见[完整色表输出与染色关联](#完整色表输出与染色关联)。

## 内嵌表入口与行坐标

`14042aca0..14042ad12` 检查 additional data 是否存在及 inline bit 2。
`14042adf9..14042ae79` 从声明取得 half4 宽度和行数，宽度指数为零时取
4 组 half4、16 行。`14042aea7` 比较宽度是否为 4 组 half4，并进入
`14042aef0..14042b06e` 的转换循环。这个分支条件来自源宽度；shader 身份
对染色 profile 的选择另见[覆盖目标证据](materials.md#染色覆盖-profile-与中间行)。

本节 `S[n]`、`C[n]` 的单位为 **half lane**，原点分别为一条源行和一条
中间行的起点。源行步长 32 字节，中间行步长 64 字节；half 原始字为小端。
`14042b049/14042b060` 的指针增量分别为 `0x20/0x40`。初始源指针先增加
`0x1c`，所以循环中的负位移必须扣除这一基址，不能直接作为源 lane。

`14042ae97..14042aea7` 对 2048 字节目标传入填充值 0。
填充助手 `141da6130..141da6254` 的大块分支分别用字节重复写入或向量
写入相同值；这里的目标是色表 payload。循环中没有另赋值的 lane 因此为零。

### 逐 lane 关系

下表描述所选转换路径在染色之前的写入；位复制保留原始 half 字。
`H` 表示该路径的 f32→half 写回，数值范围与舍入边界见下一节。

| 中间行 lanes | 来源或数值关系 | 指令范围 / 调用点 |
| --- | --- | --- |
| 0–2 | `S[0..2]` 位复制 | `14042aef0..14042af12` |
| 3、4–6 | 常量 1 | `14042af12..14042af3a` |
| 7 | `H(1 − float(S[3]))` | `14042af3a..14042af5f` |
| 8–10 | `S[8..10]` 位复制 | `14042af64..14042af7f` |
| 11 | 常量 1 | `14042af7f..14042af8e` |
| 12、13、14 | `S[4]`、`S[5]`、`S[7]` 位复制 | `14042af93..14042afae` |
| 15、17–20、23 | 初始零 | 目标填充与完整循环写入集合 |
| 16 | 常量 0.5 | `14042af84/14042afae..14042afbd` |
| 21、22、24、27 | 显式数值零 | `14042afc2/14042afd6/14042afea/14042b01b` |
| 25 | `S[11]` 位复制 | `14042affe..14042b007` |
| 26 | 常量 1 | `14042b007..14042b016` |
| 28–31 | `S[12..15]` 位复制 | `14042b027..14042b060` |

常量 1 和 0.5 分别来自 `14211bc38/14211bbd8`，原始 f32 位为
`0x3f800000/0x3f000000`。循环没有读取 `S[6]`。因此，仅从源文件字段的
公开名称推断“源 specular RGB 直接进入中间 specular RGB”与这些指令不符。
这也不能将 `C[12..14]` 在所有 shader 家族中都命名为相同光照属性。

### 行扩展与纹理参数

`14042b083..14042b1bf` 对不足 32 行的情形逐行复制已经转换的首行。
循环的源基址 `rbx` 不推进，目标每次增加 64 字节。16 行输入的来源关系为：

- 中间行 0–15 分别来自源行 0–15；
- 中间行 16–31 全部复制中间行 0。

这里没有把每个源行各复制两遍，也没有把后 16 行留作零。
图中节点标识处理阶段；行号以各表首行为 0，箭头不表示运行中已选取此路径。

#pele.diagram(r#"""
flowchart TB
  source["16 rows, 16 half lanes per row"] --> map["width-selected conversion"]
  map --> first["canonical rows 0 through 15"]
  first --> repeat["canonical row 0 copied to rows 16 through 31"]
  first --> dye["optional channel-specific dye writes"]
  repeat --> dye
  dye --> texture["8 by 32 texels, format 0x2460"]
"""#)

`14042b645..14042b682` 向纹理创建助手提供宽 8、高 32、一个 mip 和格式
`0x2460`；`14042b6cd..14042b6d8` 将所选数据指针传给已有纹理初始化入口
`140216dc0`。`0x2460` 的四通道 half 编码与每行 8×8=64 字节相符。
两个染色请求分别经 `14042b59b/14042b62e` 进入已有覆盖助手，位于这个
调用之前。这里只确定参数与先后位置，没有执行创建接口或得到上传后图像。

## 半精度写回与独立数值实验

源 lane 3 经 `140240840..1402408c6` 的 half→f32 助手后，与常量 1 作
`subss`。`140240220..1402402dd` 的反向助手在有限、结果可表示为正规
half 的分支，将 f32 尾数右移 13 位，组合符号、指数和保留尾数；没有
round-to-nearest 的加偏置或尾数进位。此范围对应向零截断，不能默认换成
语言库的 nearest-even half 转换。超范围、NaN payload、全部非正规分支及
任意运行期浮点控制状态不由这一有限范围结论代表。

`observe_legacy_color_conversion.py` 用独立数学方法检验差异：枚举所有
非负、位于 `[0,1]` 的 binary16 数，共 15361 个；以精确有理数计算 `1−x`，
逐个确认它可以被 binary32 精确表示。然后在 binary16 可表示值的有序集合中
分别按向零和距离最小/偶数规则选择结果。nearest-even 另与 Python `struct`
逐位一致。这里没有翻译 native 的指数/尾数实现，也没有执行 native 助手。
这一输入域的 `1−x` 为零或至少 `2^-11`，所以不依赖 half 写回助手的
溢出、非正规或 NaN 分支。非零结果不受舍入方向影响；精确零的符号另受
浮点控制状态影响。脚本将有理数零记录为 `+0`。`S[3]=1` 时，向负无穷
舍入的 `subss` 可产生 `−0`，而 `14024022d..14024024f` 明确区分并保留
正负零。数学行中的 `0x0000` 不承诺客户端运行时必然写出正零。

两种量化在 7680 个输入上不同。例如受控源 `0x0001 = 2^-24`：

| 数学步骤 | 结果 |
| --- | --- |
| 精确 `1−x` | `16777215 / 16777216` |
| 向零 half | `0x3bff`，即 `0.99951171875` |
| nearest-even half | `0x3c00`，即 `1` |

这些是量化规则的受控反例，不是游戏资源样本或客户端输出快照。
完整控制行摘要为
`77e4cd17eb81ceca12e30cbce39a13ae03ad6a2a5c7c34a99393a1e810621ba5`。

## 实际源值对假设的判别

输入复用[角色 Legacy 材质调查](materials.md#角色主索引的-legacy-材质调查)
的 322 份完整 512 字节 dataset 材质。先校验固定库存报告 SHA-256
`5895cfd295b30748d8b3719e4fb82660367661ca99729180871295055fd8d430`，
再逐份核对原始文件长度/摘要、版本、内嵌声明、shader 名和源行边界。
没有重复主索引扫描。5152 条源行的 lane 3 分布是：

| 原始 half | 数值 | 行数 |
| --- | ---: | ---: |
| `0x0000` | 0 | 56 |
| `0x2e66` | 0.0999755859375 | 1 |
| `0x3c00` | 1 | 5079 |
| `0x4d00` | 20 | 16 |

`ffxiv/040000.win32.dat0@187607552` 的 row 0 是明确的有限负数推论见证：
源 lane 3 为 20，所选静态公式产生 −19，恰好可表示为 half `0xccc0`。
文件 SHA-256 为
`a7de0dd5dd901a227a75e8b8d0eefa01dcaefe24d2a63b9547f6cab7e38f2195`，
shader 名为 `characterlegacy.shpk`。同文件的偶数行及另一个位于
`dat0@215041024` 的文件合计 16 行有这一数值。该公式路径未出现限幅；
把中间 lane 7 强制限制在 `[0,1]` 会改变这些输入的数值结果。没有由此宣称
运行中的这两个材质已经产生了 −19 的上传值。

各假设比较的范围如下：

- 将 `S[3]` 直接复制为 `C[7]`：全部 5152 行与 `1−x` 推论不同。
- 将 `S[4..6]` 复制为 `C[4..6]`：124 行与固定 1 的写入不同。
- 将 16 行相邻成对复制成 32 行：仅比较 14 个位复制 lane 的源值投影，
  53 份材质的 497 个目标行位置与上述首行扩展不同。报告保留具体位置、
  两个候选源行和首个不同 half；没有生成伪装为 native 输出的完整色表。
- 后 16 行补零：322 份材质的全部 5152 个尾部行，其位复制字段投影都与
  首行扩展不同。
- 向零与 nearest-even：这批实际 lane 3 的四个值没有产生差异。因此只用
  这批实材质做数值对照，不能区分两种舍入；前节控制语料才提供判别输入。

行扩展的具体反例为 `ffxiv/040000.win32.dat0@1567997696`：目标行 11
在所查路径对应源行 11，其 lane 0 为 `0x3ec6`；成对复制假设会选源行 5，
同 lane 为 `0x3c00`。源文件 SHA-256 为
`91c266163095ab8df3d12f6f493a420956b7206d4cbb0d6ed8321caa213909a2`。

这些计数是实际源值对明确假设的判别，不增加实际转换成功、染色成功或
544 字节 Legacy dye 样本的计数。

## 完整色表输出与染色关联

### 染色记录、资源选择和基础表

以下事实来自同一固定客户端的完整相邻区间，地址均为首选 VA。
`color-table-observations.json` 固定区间摘要和三处资源路径的 RIP 引用：

- `14042b1bf..14042b430` 将 16 个 Legacy u16 分解为低五位 flags 和
  高十一位模板，生成通道为零的前 16 条四字节记录；128 字节记录区的
  后 64 字节为零。颜色行 16–31 的首行复制不复制染色资格。
- `14042b525..14042b633` 分别检查两个 stain 字节非零及 additional bit 3，
  请求通道为 0、1。现代源表在有覆盖请求时复制全部 2048 字节，Legacy
  在转换时生成基础表。因此一次求值的源是文件颜色，不是上次染色结果。
- `14042b750..14042b7a2` 将材质 shader 与 utility `+0x2b8` 比较；相等
  选择 `+0x308` 和五列 profile，否则选择 `+0x300` 和十二列 profile。
  `140426c63..140426c7c` 将 `characterlegacy.shpk` 资源存入 `+0x2b8`。
  `140426e06..140426e80` 固定 `+0x300` 来自 `stainingtemplate_gud.stm`、
  `+0x308` 来自 `stainingtemplate.stm`，两者位于 `chara/base_material/`。
- `14042b7b4` 跳过零 flags；`141883cf0..141883d35` 的模板查询在 ID
  不存在时返回零，`14042b7e0..14042b7e3` 保留该行。`14042b7fd` 检查
  通道，2/3 不匹配两个请求。specular 的三半字全零保留规则沿用前页。
- `141883d52..141883d6f` 将 stain 254/255 归为零哨兵；
  `141883db9..141883e21` 在此情形向所选列目标写零，specular 仍受其
  全零保留门控。库整表操作对 254/255 明确报错；有效输入为 0–253。

这些事实闭合内嵌表转换、profile、双通道与 reset 的数据关系；外部颜色
纹理的查找和 shader 像素运算属于其他消费路径。

### 全 binary16 域的算术契约

half→f32 助手对正规数和无穷保留符号，NaN 尾数左移 13 位。非正规
输入使用 `142141244` 的 −0.5 作精确抵消，零常量 `142141240` 为 −0。
f32→half 助手对 NaN 写入同符号 `0x7e00`，无穷保持符号；正负零分支
分别保留零符号。有限正规分支截去 13 个尾数位。

完整转换约定 binary32 减法 round-to-nearest/ties-to-even、浮点异常屏蔽，
再作 half 向零截断。SSE 动态舍入模式没有由离线证据确定，库将这个
数值 profile 明确写入 API 契约，使用整数计算避免受宿主状态影响。
输入 NaN 产生同符号 quiet NaN；±∞ 分别得到 ∓∞；`S[3]=1` 得到 +0。

有限域可用数学边界消除不必要的转换分支：每个 binary16 数都是 `2^-24`
的整数倍，`1−x` 在 `[-65503,65505]` 内，除零外绝对值至少 `2^-11`。
binary32 舍入后仍在这一边界内，因此本表达式不会进入 half 写回助手的
非正规、下溢或溢出路径。Rust 在这个定点域计算差值，先取 24 位有效数字
并按偶数规则舍入，再截成 11 位有效数字；这不是通用客户端 half 助手的
指数分支翻译。

独立 Python oracle 用 `Fraction` 求精确差、`struct` 完成 binary32 舍入，
再从有序 binary16 值集合中按绝对值选择向零结果。65536 个输入包含
63488 个有限数、2 个无穷、2046 个 NaN；1024 个有限输入在 binary32
阶段改变精确差值，只有源值 1 得到零。完整结果摘要为
`1b236a653d84dd3977d5106717554e19113e1f8bf8f9f7745eca22dbdaa8cc76`。
Rust 单元回归另使用独立 f64 数值公式与有序 half 集合穷举同一输入域。

### 完整输出对照

`verify_color_tables.py` 验证源身份后构造独立完整结果。位复制关联来自
固定 lane 记录，染色目标直接从 executable 的两张数据表读取，STM 数值
由 Python 累积偏移/字典解码器取得。每个请求比较基础表 2048 字节、最终
表 2048 字节、32 个写入掩码、缺模板行掩码与 profile，共 4229 字节：

| 输入类别 | 完整请求数 | 有覆盖写入的行数 | 缺模板保留行数 |
| --- | ---: | ---: | ---: |
| 322 份实际 Legacy 512 字节材质 | 322 | 0 | 0 |
| 两份实际 32 行 dye 材质，含 `characterlegacy.shpk` | 510 | 2277 | 0 |
| 覆盖全部 half 位模式的受控 Legacy 表 | 4096 | 0 | 0 |
| 两种源尺寸 × 两种 profile × 全部 86 个真实 STM 模板 | 688 | 7568 | 0 |
| 受控缺模板与零 flags | 4 | 0 | 48 |

总计 5620 个完整表请求逐字节一致。实际 Legacy 输出拼接 SHA-256 为
`d7bd69cd186909bb27287c794a8a62055de89063771ab610396652408e92f217`；
其中源值 20 的行在库输出中产生 −19。受控 Legacy dye 表用于检验前 16 行
染色和后 16 行保留基础行，不能计为实际 544 字节资源。双通道输入覆盖
0–253，基础表不可变，reset 返回基础值；缺 STM、错误版本与非法 stain
的错误路径另有单元回归。

```sh
nix develop -c cargo build --example validate_color_tables --locked
python -B tools/verify_color_tables.py /path/to/game/ffxiv_dx11.exe \
  /tmp/opencode/render-regression-suite-39 /tmp/opencode/color-table-check
```

第二参数目录也可来自资源回归入口，需有相同身份的 `inputs/` 与
`mtrl-legacy-inventory/`。工具不扫描安装；`tables.json` 保存每个输入、
请求、基础输出与最终输出的摘要。固定报告 SHA-256 为
`9ebad014ea3225a7b355bebee05874fc9b075897c1a3ab73064313838adfb027`，
23766980 字节的完整结果 SHA-256 为
`a6926c6e3b074041c62e4218761fe7475bdf1ae86f65f27607c10c02f76bb693`。

这是可运行的库输出与独立静态规则/数学 oracle 对照；没有执行客户端、
模拟其函数或取得运行时上传快照。实际 544 字节 Legacy dye、任意动态
MXCSR 状态与最终 shader 效果各自保留证据边界。

### 公开检索接触记录

检索 Legacy/Dawntrail 转换时，搜索服务返回 XIV Modding 的 colorset 与
shader reference 页面摘要，以及 `docs.xiv.zone/docs/src/physis/mtrl.rs.html`
的未固定版本源码片段，片段自带 `GPL-3.0-or-later` 标识。未固定片段不作为
本转换的规格或实现依据；没有继续读取、复制或引入 Physis。搜索也返回
FFXIVClientStructs Texture 片段，未将其用于本色表规则。

这些接触记录与安装二进制的静态推导分别保留，不宣称严格 clean-room。
